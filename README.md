# rss-ko

외국어 RSS 피드를 한글 제목·요약으로 통합한 피드 (하루 4회 자동 갱신: 08/11/14/17시 KST, GitHub Actions `update-feed.yml`).

- 구독 주소: https://hahnjunhee.github.io/rss-ko/feed.xml
- 원본 피드 목록: `feeds.txt` (한 줄에 하나)
- `seen.json`: 처리 이력 / `items.json`: 피드 데이터 / `scripts/update_feed.py`: 빌더

API 키가 필요 없다. 피드 본문에서 핵심 문장 3개를 고르고(추출 요약) Google 번역으로 한글화한다. 번역은 비공식 엔드포인트라 가끔 실패할 수 있고, 실패한 글은 다음 실행에서 재시도한다. 수동 실행: Actions → Update feed → Run workflow.

## 번역 품질·안정성 처리 (`scripts/fetch_and_summarize.py`)
- **요약 선택:** 푸터·구독/공유 문구·해시태그를 제거하고, 단어 빈도·제목 일치·앞 문장·숫자 포함으로 문장 3개를 고른다. 일본어·중국어는 문자 2-gram으로 점수를 매긴다. 문장이 3개 이하이거나 발췌가 짧으면 줄이지 않고 그대로 번역한다. 제목을 되풀이한 문장(토큰 60% 이상 겹침)과 `◆ ■ ・ ※ -`로 시작하는 소제목·목록 줄은 후보에서 빼고(전부 해당하면 모두 후보), 제목 겹침 가산점은 2점으로 제한한다. 앞 문장 가산점을 높이고(6/순번) 일본어·중국어 15자·그 외 25자 미만 문장은 감점해 "○○です．" 같은 인사·자기소개 문장이 뽑히지 않게 한다.
- **입력 정리:** HTML을 텍스트로 바꿀 때 문단·제목 경계에 공백을 넣어 문장이 붙지 않게 하고, 제로폭 문자를 제거한다. "続きをみる"·"더 보기" 같은 더 보기 문구와 일본어 전각 마침표(．)도 처리한다.
- **잘림 방지:** 번역이 원문보다 비정상적으로 짧으면(일본어·중국어 원문은 45% 미만, 그 외 25% 미만) 다음 엔진 결과와 비교해 더 긴 쪽을 쓴다. clients5 응답의 여러 구간은 모두 이어 붙인다. 두 엔진 모두 짧게 주면 먼저 `『』「」` 같은 괄호를 따옴표로 바꿔 한 번에 다시 번역하고(번역 후 원래 괄호로 복원), 그래도 짧으면 괄호·문장부호 뒤 공백 기준으로 2~6조각으로 나눠 따로 번역해 이어 붙인다(영어 단어 단위로는 나누지 않는다).
- **원문 수집(선택):** `fulltext.txt`에 적은 호스트(기본 `note.com`)의 글 중 RSS 발췌가 잘렸거나(`続きをみる`·`…`·`Read more`) 300자 미만인 글만 공개 원문을 가져와(`trafilatura`, 댓글 제외) 요약 대상으로 쓴다. robots.txt를 지키고(4xx면 허용, 서버·네트워크 오류면 불허), 호스트당 1.5초 간격·응답 2MB 상한·허용 호스트 밖 리다이렉트 거부·실행당 최대 30건으로 제한한다. 유료 구간("ここから先は有料")은 잘라내고, 추출이 실패하거나 발췌보다 50자 이상 늘지 않으면 RSS 발췌를 쓴다. **피드에는 원문 전문이 아니라 3문장 요약과 원문 링크만 싣는다.** 개인 구독용으로만 쓰고 공개 서비스로 바꾸지 말 것. 호스트를 늘리려면 `fulltext.txt`에 한 줄 추가. `trafilatura`가 설치되지 않으면 이 기능만 꺼지고 나머지는 그대로 동작한다.
- **재시도:** 429·5xx·타임아웃·빈 응답은 2번까지 5초·15초(429의 Retry-After가 있으면 그 값, 최대 60초) 대기 후 다시 시도한다. 호출 사이에는 1.5초 쉰다. 글이 연속 3건 실패하면 서비스 장애로 보고 그 실행의 나머지를 건너뛰며, 맨 뒤에서 연속 실패한 글은 게재하지 않고 다음 실행에서 다시 한다.
- **번역 엔진 폴백:** Google 무료 경로 3개(`translate.googleapis.com` → `clients5.google.com` → `translate.google.com/m`)를 순서대로 시도한다. GitHub 러너 IP가 429로 막히는 경우 다른 경로가 통할 수 있다. 한 경로가 한 실행에서 연속 3번 실패하면 나머지 호출에서는 건너뛴다. 실행 로그와 실행 요약에 `번역 엔진 사용: {...}`과 경로별 실패 횟수·마지막 오류가 남는다. 셋 다 비공식이라 언제든 바뀌거나 막힐 수 있다.
- **원문 임시 게재:** 같은 실행에서 다른 글은 번역에 성공했는데 한 글만 실패하면 그 글은 원문 제목·요약으로 올리고(`untranslated`), 다음 실행에서 최대 3번까지 다시 번역한다. 한 글만 계속 실패하고 그 실행에 성공한 글이 없으면 시도 횟수는 늘지 않는다.
- **번역 캐시:** `translations.json`에 `sha1(처리 버전 + 원문)` → 번역을 저장한다(최대 1000개). 요약·번역 규칙을 바꾸면 `PROCESS_VERSION`을 올린다. 과거 글을 자동으로 다시 번역하지는 않는다.
- **품질 비교(dry-run):** Actions → Update feed → Run workflow에서 `dry_run`을 켜면 이미 처리한 글까지 최대 30건을 요약·번역하되 피드·items·seen은 바꾸지 않고, 결과를 `dry-run-items` 아티팩트로 저장하고, 원문 요약과 번역을 나란히 보여 주는 샘플 10건을 로그와 실행 요약에 남긴다. 숫자 누락·빈 번역·한글 비율 낮음은 로그 경고로 표시한다. 로컬: `python scripts/fetch_and_summarize.py --dry-run`.
